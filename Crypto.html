CHAPTER 01

密码学概览

密码学是研究信息系统安全保密的学科，核心目的在于保证信息的机密性、完整性、认证性和不可否认性。密码算法大小写敏感，密钥空间决定安全性。

密码学核心属性

  • 机密性 (Confidentiality) —— 确保信息只能被授权方访问，未被授权者无法理解内容
  • 完整性 (Integrity) —— 确保信息在传输或存储过程中未被未授权篡改
  • 认证性 (Authentication) —— 验证通信方身份的合法性，确认数据来源可信
  • 不可否认性 (Non-repudiation) —— 发送方无法否认其已发送过的信息，接收方无法否认其已接收的信息

柯克霍夫原则

密码系统安全性应只依赖于密钥的保密性，而非算法的保密性。即使算法被完全公开，只要密钥未泄露，系统仍应安全。

CHAPTER 02

对称加密体制

加密和解密使用相同密钥的加密算法，加解密速度快，适合对大批量数据进行加密，但密钥分发面临极大挑战。

两大核心分组模式

  • 分组密码 —— 将明文分成固定长度的块，逐块加密（如AES, DES）
  • 流密码 —— 将密钥扩展为无限伪随机密钥流，逐位加密（如RC4, ChaCha20）

常见分组工作模式

  • ECB 电子密码本模式 —— 相同明文块产生相同密文块，不安全
  • CBC 密码分组链接模式 —— 每个明文块先与前一个密文块异或再加密，需IV
  • CTR 计数器模式 —— 将计数器加密后与明文异或，可并行计算
  • GCM 伽罗瓦/计数器模式 —— 提供机密性与数据完整性的认证加密
symmetric-encrypt.sh 
# 使用 AES-256-CBC 加密文件
openssl enc -aes-256-cbc -salt -in plaintext.txt -out ciphertext.enc -pass pass:YourSecretKey

# 使用 AES-256-CBC 解密文件
openssl enc -d -aes-256-cbc -in ciphertext.enc -out decrypted.txt -pass pass:YourSecretKey

# 使用 ChaCha20 加密（需较新版本OpenSSL）
openssl enc -chacha20 -in plaintext.txt -out chacha.enc -K [64位十六进制密钥] -iv [32位十六进制IV]
SECURITY ALERT

DES 算法密钥长度仅为56位，已可被暴力破解，严禁用于生产环境。ECB模式因无法隐藏数据模式，同样不应使用。

CHAPTER 03

非对称加密体制

加密和解密使用不同的密钥对：公钥公开用于加密或验证，私钥保密用于解密或签名。解决了密钥分发问题，但计算开销远大于对称加密。

核心算法

  • RSA —— 基于大质数分解难题，最广泛使用的非对称算法，推荐密钥长度2048位以上
  • ECC 椭圆曲线密码学 —— 基于椭圆曲线离散对数难题，256位ECC安全强度等同于3072位RSA
  • ElGamal —— 基于离散对数难题，常用于数字签名与密钥交换
asymmetric-crypto.sh 
# 生成RSA 2048位私钥
openssl genrsa -out private.pem 2048

# 从私钥中提取公钥
openssl rsa -in private.pem -pubout -out public.pem

# 使用公钥加密文件
openssl rsautl -encrypt -pubin -inkey public.pem -in msg.txt -out msg.enc

# 使用私钥解密文件
openssl rsautl -decrypt -inkey private.pem -in msg.enc -out msg.dec

# 生成ECC私钥和公钥（prime256v1曲线）
openssl ecparam -name prime256v1 -genkey -noout -out ec-private.pem
openssl ec -in ec-private.pem -pubout -out ec-public.pem
CHAPTER 04

散列函数与完整性

散列函数将任意长度的输入映射为固定长度的输出，具有单向性和抗碰撞性，不使用密钥，用于验证数据完整性。

核心特性

  • 单向性 —— 从散列值无法逆向推导出原始数据
  • 抗弱碰撞 —— 给定一个输入，无法找到另一个输入产生相同的散列值
  • 抗强碰撞 —— 无法找到任意两个不同输入产生相同的散列值
  • 雪崩效应 —— 输入的微小变化导致散列值发生巨大变化

常见散列算法对比

算法输出长度安全状态典型应用
MD5128 bit已破解仅用于校验，非安全场景
SHA-1160 bit不推荐遗留系统
SHA-256256 bit安全TLS, 数字签名, 区块链
SHA-3可变安全新一代标准，海绵结构
hash-examples.sh 
# 计算文件的 SHA-256 散列值
sha256sum filename.txt

# 计算字符串的 MD5 散列值
echo -n "password" | md5sum

# 使用 OpenSSL 计算 SHA-512
echo -n "data" | openssl dgst -sha512

# HMAC 带密钥的散列
echo -n "message" | openssl dgst -sha256 -hmac "secret_key"
HMAC

Hash-based Message Authentication Code，使用密钥与散列函数组合，既验证数据完整性又验证消息来源的真实性。

CHAPTER 05

密钥管理

密钥是密码系统的核心资产，密钥管理的安全性直接决定整个系统的安全性。涵盖密钥生成、分发、存储、更新、撤销与销毁全生命周期。

密钥生命周期

  • 生成 —— 使用安全随机数生成器(CSPRNG)生成，避免伪随机
  • 分发 —— 通过安全信道或密钥交换协议传递密钥
  • 存储 —— 使用硬件安全模块(HSM)或密钥管理系统(KMS)保护
  • 轮换 —— 定期更新密钥，降低密钥泄露影响
  • 撤销与销毁 —— 安全擦除密钥数据，确保不可恢复
keygen.sh 
# 生成高质量随机密码/密钥（十六进制）
openssl rand -hex 32

# 生成 Base64 编码的随机密钥
openssl rand -base64 32

# 从 /dev/urandom 读取随机字节
head -c 32 /dev/urandom | xxd -p

# 使用 SSH 密钥对（Ed25519，推荐）
ssh-keygen -t ed25519 -C "user@host" -f ~/.ssh/id_ed25519

# 使用 SSH 密钥对（RSA，兼容性更好）
ssh-keygen -t rsa -b 4096 -C "user@host"
CHAPTER 06

公钥基础设施与数字证书

PKI 是创建、管理、分发、使用、存储和撤销数字证书以及管理公钥加密所需的一组角色、策略、硬件、软件和过程的集合。

核心组件

  • CA 证书颁发机构 —— 可信第三方，签发与管理数字证书
  • RA 注册机构 —— 验证证书申请者身份，代理CA处理申请
  • 证书库 —— 存储已签发证书的公开数据库，供查询下载
  • CRL 证书撤销列表 —— 列出已被撤销的证书序列号
  • OCSP 在线证书状态协议 —— 实时查询证书是否被撤销

CHAPTER 07

证书签名与验证

数字证书由CA签发，通过CA的私钥签名来保证证书的真实性和不可篡改性。

cert-ops.sh 
# 生成自签名证书（测试用）
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365 -nodes

# 生成证书签名请求(CSR)
openssl req -newkey rsa:2048 -keyout server.key -out server.csr

# 使用CA私钥签发证书
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365 -sha256

# 验证证书链
openssl verify -CAfile ca.crt server.crt

# 查看证书详情
openssl x509 -in cert.pem -text -noout

# 检查证书是否过期
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates
CHAPTER 08

数字签名

数字签名是发送者用自己的私钥对消息散列值进行签名，接收者用发送者的公钥验证。确保了消息的完整性、认证性和不可否认性。

签名流程

  • 签名 —— 发送者计算消息散列值 → 用私钥加密散列值 → 生成数字签名
  • 验证 —— 接收者用发送者公钥解密签名 → 计算收到消息的散列值 → 比较两者是否一致
digital-signature.sh 
# 使用RSA私钥对文件签名（SHA-256）
openssl dgst -sha256 -sign private.pem -out document.sig document.txt

# 使用RSA公钥验证签名
openssl dgst -sha256 -verify public.pem -signature document.sig document.txt

# 签名并分离签名文件
openssl cms -sign -in message.txt -signer signer.crt -inkey signer.key -outform DER -out message.p7b

# GPG 签名与验证
gpg --sign document.txt          # 生成 document.txt.gpg
gpg --verify document.txt.gpg # 验证签名
gpg --clearsign document.txt  # 生成可读的签名文档
CHAPTER 09

密钥交换协议

在不安全的信道上安全地协商出共享密钥的协议，使通信双方无需事先共享秘密即可建立加密通信。

Diffie-Hellman (DH) 密钥交换

  • 基本原理 —— 基于离散对数难题，双方各自生成私钥，交换公钥参数后计算出相同的共享密钥
  • ECDH —— 椭圆曲线版DH，更短密钥达到同等安全强度，性能更优
前向保密 (Forward Secrecy)

如果长期密钥泄露，过去的会话密钥不会被推导出来。通过临时密钥交换(DHE/ECDHE)实现，每次会话使用不同的临时密钥对。

key-exchange.sh 
# 生成 DH 参数（2048位）
openssl dhparam -out dhparam.pem 2048

# 生成 ECDH 密钥对
openssl ecparam -name prime256v1 -genkey -noout -out ecdh_key.pem

# 查看支持的椭圆曲线
openssl ecparam -list_curves
CHAPTER 10

加密通信与TLS

Transport Layer Security 是互联网安全通信的基石，在传输层提供加密、身份验证和完整性保护。HTTPS 即 HTTP over TLS。

TLS 1.3 握手流程

  • ClientHello —— 客户端发送支持的密码套件列表、密钥共享(DH公钥)和随机数
  • ServerHello —— 服务器选择密码套件，发送DH公钥、随机数和证书
  • 验证与密钥计算 —— 双方基于DH交换计算共享密钥，客户端验证服务器证书
  • 加密通信 —— 仅1-RTT即可开始应用数据传输，支持0-RTT恢复
tls-tools.sh 
# 查看网站证书信息与TLS版本
openssl s_client -connect example.com:443 -tls1_3

# 检查服务器支持的TLS协议版本
nmap --script ssl-enum-ciphers -p 443 example.com

# 使用 curl 测试TLS连接详情
curl -vI https://example.com 2>&1 | grep "SSL connection"

# 使用 testssl.sh 全面评估TLS配置
./testssl.sh example.com
SECURITY ALERT

TLS 1.0 和 TLS 1.1 已被正式废弃。SSL 3.0 及更早版本存在严重安全漏洞（如 POODLE），严禁使用。生产环境应仅启用 TLS 1.2 和 TLS 1.3。

CHAPTER 11

常见密码分析

密码分析是研究破解密码系统的方法论，了解攻击手段有助于设计更安全的系统。

攻击类型分类

  • 唯密文攻击 —— 攻击者仅拥有密文，难度最大
  • 已知明文攻击 —— 攻击者拥有部分明文-密文对
  • 选择明文攻击 —— 攻击者可选择任意明文获取对应密文
  • 选择密文攻击 —— 攻击者可选择任意密文获取对应明文，最强攻击模型

经典攻击手段

  • 暴力破解 —— 遍历整个密钥空间，复杂度取决于密钥长度
  • 字典攻击 —— 使用常见密码/密钥列表进行尝试
  • 彩虹表 —— 预计算散列链表，用空间换时间破解散列
  • 侧信道攻击 —— 利用时间消耗、功耗、电磁泄漏等物理信息推断密钥
  • 填充神谕攻击 —— 利用CBC模式填充验证错误消息反馈逐字节解密
加盐 (Salt)

在散列计算前加入随机值（盐），使得相同密码产生不同散列值，有效抵御彩虹表攻击。盐值应足够长且每个用户独立。

CHAPTER 12

抗量子密码学

量子计算机运行 Shor 算法可在多项式时间内分解大整数和计算离散对数，将威胁RSA、ECC等现有非对称加密体系。抗量子密码学(PQC)旨在抵御量子计算攻击。

NIST PQC 标准化算法

算法类别数学基础用途
CRYSTALS-KyberKEM格密码密钥封装
CRYSTALS-Dilithium签名格密码数字签名
FALCON签名NTRU格数字签名（紧凑）
SPHINCS+签名散列无状态签名
Harvest Now, Decrypt Later

攻击者可能现在截获并存储加密数据，等待未来量子计算机成熟后再解密。涉及长期机密性的数据应立即考虑迁移至PQC方案。

CHAPTER 14

密码学最佳实践

安全不仅仅是选择算法，更在于正确地使用和实施。以下是密码学工程实践中的核心原则。

黄金法则

  • 不要自己发明密码算法 —— 使用经过广泛审查的标准算法和库
  • 不要复用密钥和IV —— 相同密钥必须搭配不同的初始化向量
  • 优先选择认证加密(AEAD) —— 如 AES-GCM, ChaCha20-Poly1305，同时保障机密性与完整性
  • 密钥必须安全存储 —— 使用HSM、KMS或系统密钥链，禁止硬编码
  • 安全随机数是根基 —— 使用 /dev/urandom 或密码学安全PRNG，不要用 random()
  • 持续更新与轮换 —— 关注算法安全动态，及时升级密钥长度和算法版本
  • 防御纵深 —— 不依赖单一安全机制，多层防护
best-practices.sh 
# 密码存储最佳实践：使用 Argon2 / bcrypt / scrypt

# Python - Argon2 (推荐)
pip install argon2-cffi
python3 -c "from argon2 import PasswordHasher; ph = PasswordHasher(); print(ph.hash('password'))"

# Python - bcrypt
pip install bcrypt
python3 -c "import bcrypt; print(bcrypt.hashpw(b'password', bcrypt.gensalt(12)))"

# 密码学安全随机数
dd if=/dev/urandom bs=32 count=1 of=random_key.bin 2>/dev/null

# 安全擦除敏感文件（覆写后删除）
shred -vfz -n 3 sensitive_key.pem
